## 起動

初回のみ、Ollamaへ回答モデルを登録します。

```powershell
ollama pull gemma3:1b
```

次のスクリプトを実行し、12文字以上のパスワードを入力します。パスワードはコマンド履歴、リポジトリ、コンテナ環境変数へ保存されません。

```powershell
.\scripts\start.ps1
```

ブラウザで `http://localhost:8080` を開きます。既定のユーザー名は `qabot` です。変更する場合は `-User` を指定します。

```powershell
.\scripts\start.ps1 -User local-admin
```

APIとChromaDBはDocker内部ネットワーク限定です。埋め込みモデルはイメージ構築時に取得され、実行時はオフラインモードで読み込まれます。

## 検索の仕組み

質問ごとに、意味の近さで探すベクトル検索と、文字列の一致で探すキーワード検索（BM25）を両方実行し、順位を Reciprocal Rank Fusion で統合します。キーワード索引は ChromaDB の内容から API 内で作り、文書の取り込みや改訂でチャンクが変わった時だけ作り直します。

- 日本語は文字2-gram、英数字は「A-1234-05」のようなまとまりと「a」「1234」「05」の区切り単位で索引します。全角・半角の違いは区別しません。
- 質問に品番・図番・製番らしい文字列（数字を含む6文字以上、または英字と数字が混在する3文字以上。日付は除く）がある場合、その文字列を含むチャンクだけを根拠にします。`110601280` は `1106012800` には一致しません。
- 品番を含まない質問は、従来どおり類似度が `MIN_RELEVANCE` 以上のチャンクだけを根拠にします。

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `MIN_RELEVANCE` | `0.8` | 意味検索で根拠として採用する類似度の下限 |
| `SEARCH_CANDIDATES` | `20` | 各検索で取得する候補数 |
| `TOP_K` | `3` | LLMに渡す根拠チャンクの最大数 |
| `CODE_FILTER` | `true` | 品番等を含む質問で、そのコードを含むチャンクに限定するか |
